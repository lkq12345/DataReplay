# 数据回放客户端软件 — 需求文档

## 一、功能性需求

### F1. 想定管理
- F1.1 支持从 dataFiles/ 目录下自动扫描想定文件夹
- F1.2 想定文件格式为 XML，包含：想定名称、描述、仿真步长(ms)、开始时间、结束时间、实体列表（ID/名称/类型/初始属性）
- F1.3 一个想定可关联多个数据文件（约定：想定同目录下的"回放数据/"子目录中的 .txt 文件自动关联）
- F1.4 支持通过界面加载/切换想定

### F2. 数据文件读取
- F2.1 数据文件格式为 .txt，每行一条数据："时间戳 JSON" 明文格式
- F2.2 单个文件可达几百 MB，不能将全部数据加载到内存
- F2.3 按仿真步长窗口读取数据，一个步长窗口内可能包含多条数据
- F2.4 需要预扫描文件信息（数据条数、时间范围、文件大小），但不加载全文

### F3. 回放控制
- F3.1 支持初始化、开始、暂停、继续、停止五个状态
- F3.2 初始化：解析想定 + 打开数据文件（准备就绪），初始化NATS连接
- F3.3 开始：启动定时器，按步长推进
- F3.4 暂停：暂停推进，保留当前进度
- F3.5 继续：从暂停处恢复推进
- F3.6 停止：停止推进，重置回已初始化状态

### F4. 步进与发送
- F4.1 每个定时器周期取一个仿真步长的数据
- F4.2 同一仿真步长内的所有数据按时间戳排序后，全部发送出去
- F4.3 如果有多个数据文件，窗口数据需要跨文件合并并按时间戳全局排序
- F4.4 通过 NATS 发送到指定的主题
- F4.5 所有数据发往同一个 NATS 主题

### F5. 倍速控制
- F5.1 仿真步长不变，通过改变物理定时器间隔实现倍速
- F5.2 倍速范围：1~100 倍
- F5.3 倍速公式：物理间隔 = 仿真步长 / 倍速（如步长100ms，2倍速→50ms一次，一个步长的数据全部发送）
- F5.4 倍速在回放过程中实时生效，无需停止后修改
- F5.5 倍速值由用户在输入框中手动输入，做 1~100 的范围限制

### F6. NATS 通信
- F6.1 NATS 服务器地址、端口、订阅主题在配置文件中配置
- F6.2 配置文件格式：XML（已有 config/NATS/NatsConfig.xml）
- F6.3 具备断线重连机制
- F6.4 只发送（发布）数据，当前不涉及接收/订阅（但已有接收能力的代码资产可以保留）

### F7. 日志
- F7.1 日志信息在前端界面显示（带时间戳）
- F7.2 日志同时保存到本地日志文件
- F7.3 日志至少包含：操作记录（加载想定、开始/暂停等）、错误信息、系统状态

### F8. UI 界面
- F8.1 树形列表显示文件（方案一）：想定为父节点，数据文件为子节点
- F8.2 想定行显示：名称、步长、时间范围、实体数量
- F8.3 数据文件行显示：文件名、文件大小、数据条数
- F8.4 实体配置表格显示：实体ID、名称、类型、状态
- F8.5 导调控制区：初始化/开始/暂停/继续/停止按钮 + 倍速输入框
- F8.6 进度显示：当前仿真时间 + 进度百分比/进度条
- F8.7 日志显示区：带时间戳的日志信息

### F9. 前后端分离
- F9.1 APP（exe）只负责 UI 显示 + 用户交互 + 调用后端接口
- F9.2 Server（dll）负责所有业务逻辑：想定解析、文件读取、回放引擎、NATS 通信
- F9.3 APP 不直接接触 NATS 库，NATS 细节对 APP 透明
- F9.4 APP 与 Server 之间通过函数调用 + Qt 信号/槽通信

## 二、非功能性需求

### N1. 性能
- N1.1 支持读取和处理几百 MB 的大文件
- N1.2 运行时内存占用稳定（不应随文件增大而线性增长）
- N1.3 数据读取采用游标式顺序读取，避免全量加载

### N2. 可用性
- N2.1 界面响应流畅，回放过程中界面不卡死
- N2.2 状态切换有明确的反馈

### N3. 可扩展性
- N3.1 软件框架需适配未来可能的功能扩展

## 三、未来预留功能（暂不实现）

### R1. 网络接收推演数据
- R1.1 通过网络接收外部的推演数据
- R1.2 将接收到的数据保存为本地数据文件（与现有格式一致）

### R2. 值替换
- R2.1 将数据文件中的某些字段值替换后再发送
- R2.2 替换规则可配置
